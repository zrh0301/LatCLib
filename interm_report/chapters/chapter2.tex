\chapter{高兼容与高性能PQC算法库工程}

\section{PQC算法概述与工程挑战}

\subsection{格密码：为量子时代而生的新数学基石}

后量子密码（Post-Quantum Cryptography, PQC）是指在经典计算机上运行，却能同时抵御经典攻击与量子计算机Shor/Grover算法攻击的新型密码体系。在NIST最终标准化的三类PQC算法中，\textbf{基于模格（Module-Lattice）的密码学方案}最受产业界青睐——它兼顾了密钥尺寸小、运算快、安全性归约强等工程优势，已成为全球PQC迁移的事实首选。

本算法库核心支持的两大类NIST标准化格密码算法为：

\begin{enumerate}
	\item \textbf{ML-KEM（Module-Lattice-based Key Encapsulation Mechanism，FIPS 203）}：用于两方在不安全信道上协商共享会话密钥，是传统ECDH/SM2密钥协商的量子安全替代方案。ML-KEM基于模\textbf{容错学习问题（MLWE）}的困难性构造，通信双方无需传输完整密钥，而是通过密文封装机制安全派生会话密钥。
	
	\item \textbf{ML-DSA（Module-Lattice-based Digital Signature Algorithm，FIPS 204）}：用于身份认证与消息完整性验证，是传统ECDSA/SM2数字签名的量子安全替代方案。ML-DSA继承了CRYSTALS-Dilithium的``Fiat-Shamir with Aborts''构造，基于模-\textbf{SIS与MLWE}双重困难问题。
\end{enumerate}

两种算法共享相同的\textbf{代数结构根基}——多项式商环 $\mathcal{R}_q = \mathbb{Z}_q[X]/(X^n + 1)$（其中 $q$ 为素数模数，$n=256$ 为多项式次数），均依赖数论变换（NTT）作为核心计算引擎。这一天然同构性使得底层的多项式运算、哈希与采样模块可被两者\textbf{完全复用}，为后续章节阐述的紧凑工程架构铺平了道路。

\subsection{工程落地面临的三大核心挑战}

PQC算法的数学安全性已有严密的理论保障，但将这些算法从学术论文\textbf{真正工程化落地到门禁卡+NFC读卡器这类极端受限硬件平台}，面临着传统密码学从未遇到过的全新挑战。

\subsubsection{挑战一：内存开销——密钥尺寸的断崖式膨胀}

传统ECC公钥密码体系的一个突出优势是\textbf{密钥短小}。以当前最广泛使用的SM2（ECC-256）为例，公钥仅需64字节；而切换到格密码后，密钥与签名尺寸出现了\textbf{数倍乃至数十倍的数量级跃升}：

这意味着：一张原本只需存储64字节SM2公钥的门禁卡，升级到ML-DSA-44后需要存储\textbf{超过1.3KB的公钥}，签名验证时还需处理2.4KB的签名数据。对于典型无源NFC门禁卡片上仅有\textbf{约8--32KB RAM}的现实而言，单是密钥数据结构的常驻内存就已吃掉相当比例，留给计算中间变量的空间极其紧张。

\subsubsection{挑战二：通信开销——APDU帧长限制下的传输瓶颈}

NFC门禁通信遵循ISO 7816-4 APDU协议规范，读卡器与卡片之间通过非接触式射频帧交换数据。在ISO 14443 Type A/B典型配置下，\textbf{单帧有效载荷仅约256字节}（标准短APDU数据域上限255字节）。

对比两类算法的完整认证交互数据量：传统SM2双向认证仅需交换公钥（64B）+ 签名（64B）= 128B，\textbf{单帧即可完成}；而ML-DSA-44双向认证需要交换公钥（1312B）+ 签名（2420B），如果加上ML-KEM的密钥交换公钥（800B）+ 密文（768B），\textbf{总传输量逼近7.3KB}——按单帧256字节计算，需要约28次APDU往返。这一通信延迟在门禁场景下是致命的：用户体验要求\textbf{刷卡总耗时 $\le$ 300ms}，而每次ISO 14443帧交换的固有延迟约4--5ms，仅帧交换本身就将轻松突破100ms。

这里有一个容易忽视的工程事实：\textbf{在锁端/读卡器端，格密码的纯计算速度实际上已优于同安全级别的ECC}（得益于NTT将多项式乘法从$\mathcal{O}(n^2)$降至$\mathcal{O}(n\log n)$），真正拖慢整条认证链路的\textbf{不是算力，而是传输}。

\subsubsection{挑战三：资源异构——从服务端到无源卡片的两极分化}

PQC算法库面临的运行环境是高度异构的：

\begin{itemize}
	\item \textbf{后台服务端（x86/AArch64服务器）}：计算资源充裕，可部署SIMD向量化、多线程并行，但需要处理高并发门禁事件流。
	\item \textbf{门禁读卡器（ARM Cortex-M / RISC-V MCU）}：Flash通常在256KB--1MB量级，RAM 64--256KB，需要运行完整协议栈与多协议兼容逻辑。
	\item \textbf{无源门禁卡（RISC-V SE安全芯片）}：\textbf{最极端场景}——无电池，靠射频取电，片上RAM通常仅8--32KB，Flash 64--256KB，主频多限制在16--40MHz。在此环境下完成ML-DSA签名所需内存若不做任何优化，内存峰值可达到20--40KB，\textbf{已超出多数无源NFC芯片的物理上限}。
\end{itemize}

这三大挑战并非互不相干：内存不够会导致不得不做更多分批计算（耗时增加），更多APDU交换又拉长通信链路（总延迟上升），而服务端的高性能实现和卡片端的极限裁剪之间又存在巨大的\textbf{代码复用鸿沟}。接下来各节将逐层展开：\textbf{2.2节}阐述卡片端如何将算法内存压至3KB以内并重构通信模型；\textbf{2.3节}讨论锁端/服务端的高性能SIMD与RISC-V向量化策略；\textbf{2.4节}则给出贯穿三层的四层解耦合兼容架构。
